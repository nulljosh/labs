# README voice (a little me, a little Jobs)

Structure, in order. Short paragraphs. One idea each. No bullet walls, no jargon, no emojis, no em dashes.

1. **Name.** Just the name.
2. **The problem, as a punch.** One sentence you'd say out loud. Then two or three concrete ways it hurts. End on "That's the gap." or similar.
3. **What it does.** Plain description of the mechanism. Then show the moment it pays off as a quote or example. Close with "That's it. That's the whole product."
4. **Why this and not the obvious thing.** One comparison, one metaphor. Weather report vs someone knocking with an umbrella.
5. **Where it goes.** v0, v1, then the business. Three sentences max.
6. **Run it.** Code blocks only. Config, endpoints, secrets, commands, live URL.

Write like you're explaining it to a friend who'll get it in ten seconds. The Jobs part is the arc: pain, reveal, one-line summary, "and one more thing". The me part is the words.
