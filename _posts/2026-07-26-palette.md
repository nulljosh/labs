Tonight was all about app icons. I spent the evening recoloring five app icons from monochrome black to distinct brand colors, exported all the variants into each app's icon sets, bumped versions, and pushed every one to the App Store for review.

## Sunday

Went through each app's icon.svg—Litigate, Lexly, Epiphany, Talli, Echo—and shifted the background colors from near-black to something with personality: deep navy, sky blue, emerald green, amber, and teal. Regenerated all the iOS/macOS icon variants, sized them correctly for App Store Connect, and uploaded them all in a single push.

Each app got a version bump to ship with the new icons (Litigate 1.0.2, Lexly 1.1.2, Epiphany 2.5.3, Talli 3.5.10, Echo 1.3.4). All five are now submitted to the App Store for review. While archiving the apps, I found and fixed a stale reference in Litigate's `.asc/workflow.json`—it was still pointing to the old "Brief" and "Casewright" names from before the app was renamed to Litigate. Updated it to reference the correct app name and scheme.

Later that evening, I caught an issue with Epiphany's TestFlight screenshot—the node-graph icon was almost invisible against the background. The nodes and lines were too close to the background color, making them nearly impossible to see. I fixed the contrast by making the nodes white and increasing the line opacity across all three icon files (iOS, macOS, and the root icon), then regenerated all the icon variants and stripped the alpha channels per App Store requirements. Changed the background to Olive from my color system as well, giving the icon both better readability and more personality.

After submitting that batch, I went back to Echo's icon and redesigned it completely. The teal snowman-circle pattern didn't feel right for a speech-transcription app. Replaced it with a clean microphone glyph on the clrs.cc blue background—sharper, more on-brand, and immediately readable as voice input. Regenerated all the iOS and macOS icon variants with the new design. Echo is already in App Store review with the old icon (v1.3.4), so I'll bump it to v1.3.5 after that version clears review.

The Talli work turned into the evening's real discovery. I'd recolored the icon to amber earlier, but it looked washed out compared to everything else. While reverting it, I noticed something odd in the build logs—the version number kept resetting to an old value even after I'd bumped it. Dug into project.yml and found it: xcodegen was regenerating the Xcode project every build, and somewhere in the config, the MARKETING_VERSION was hardcoded to an earlier value. That's why Xcode Cloud had been failing all weekend—the version train kept colliding with itself. Fixed the version.yml/pbxproj drift, then redesigned the icon properly with a bold clrs.cc blue background and centered white tally marks. Much sharper than the amber, and the marks are high-contrast now.

Went back to Talli again later to try shipping the blue icon fix and bumped to v3.5.11. The build archived, exported, and uploaded to App Store Connect cleanly, and it's sitting there VALID. But attaching it to an actual version to submit failed: Apple won't let me create a new version while 3.5.10 (this morning's amber-icon submission) is still in review. Same version-train restriction as the weekend bug, just a different flavor of it. The build is safely uploaded and ready, I just have to wait for 3.5.10 to clear before I can attach and submit it.

## Monday

Tonight I spent some time evaluating build and distribution automation alternatives—Tuist, Danger, Mint, and fastlane match—to see if any would improve the app release workflow. Turns out the existing tooling (asc CLI, xcodegen, and the asc-signing-setup skill) already handles everything those tools do. Decided to skip adding anything new and keep the current setup as-is.
