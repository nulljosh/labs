## Sunday

Simplified Echo's web frontend tonight—replaced the external Google Fonts dependency with the system font stack and pulled the italic styling from the headers. Faster rendering, smaller bundle, one less third-party resource to worry about. After pushing the commit, discovered the landing page isn't hosted on Vercel like most other projects—it lives on Cloudflare Pages with no git auto-deploy, so the deployment requires a manual `npx wrangler pages deploy web/ --project-name=echo` step after every push.

Spent the rest of the evening doing a font audit across the web tier—Echo, Spine, and Sparkjar all had external typeface dependencies I could rip out. Replaced Google Fonts and Fraunces with the system stack (Geist for body text, SF Pro / Helvetica for display), streamlined italic styling, and committed the changes across all three projects. While fixing Sparkjar's web build, spotted a bug in the YC Requests for Startups scraper—the regex was anchoring the author capture to `</a></span>`, but YC bylines have text after that marker, so it was pulling text from multiple entries and dumping it as one massive label. Re-anchored to just `</span>` and it parsed all 13 entries cleanly. One theme: third-party font loading adds latency, bundle size, and runtime complexity for something the browser's system fonts already do better. Updated the wiki and journal with the changes.

Also fixed two old Epiphany bugs that turned out to be the same class of mistake. The Flights panel had been broken since day one—turns out the bboxFromCenter function's default `deg` parameter of 2 was being used as a full span instead of a half-span, so it was building 4-degree boxes. The flights API rejects anything over 2 degrees with a 400 error. The map's flight layer worked fine because it builds its own bbox, which is why it looked like a contradiction. Same bug was in the iOS and macOS clients—they were sending the raw map-region span directly, which broke flights whenever zoomed out. Now the flights layer clamps to 2 degrees around map center. Also untangled Portfolio's "Could not load saved statements" error—the refresh callback was recreated on every portfolio change, triggering a refetch loop on success. Held it in a ref, cleared the error on success, and the statement list came back. Tested both against production and verified the server was healthy all along. Put the People tab and Daily Brief behind the Pro tier (account tier now gates both client and server), set my account to Pro in Upstash KV, and stripped out the read-only API toggle and manual sync button from Settings since Portfolio auto-syncs and polls every 5 minutes anyway.

On the Spine side, added a new "To Read" section backed by a `toRead` array in the bundled library.json, starting with How to Cheat at Everything and Hackers & Painters. Finished summarizing chapters 11–15 of IBS For Dummies from iCloud photos and merged them into the existing summary, added the Summary badge to the web listing, and indexed it in the iOS app.

## Monday

Wrapped up weekend work this afternoon. All font changes and parser fixes tested and verified—npm test passed on sparkjar (34 passed, 6 skipped). Updated notes wiki and CLAUDE.md for what landed. No remaining blockers across any of the touched projects; all builds clean.

Fixed a long-standing Epiphany iOS entitlement bug: xcodegen regenerates the Xcode project on every run, and when a capability in project.yml has no `properties:` block defined, xcodegen silently empties it to `<dict/>` and strips the entitlement entirely. This was happening to the applesignin capability — the target declared a path to `ios/Epiphany.entitlements` but xcodegen had no knowledge of what properties to add, so every regenerate would wipe it out and disable Sign in with Apple on iOS. Fixed by adding the explicit `properties:` block to the applesignin capability in project.yml (commit 39d7102). iOS BUILD SUCCEEDED, pushed to main.
