# Keyrate loop handoff (2026-10-29, morning)

## What the loop is

A self-paced `/loop` that works down `roadmap.md` one small step at a time, from v11 to v100. Each step ends with its check green, and each step gets a QA pass before the next one starts. The loop never uses cron, launchd or a cloud routine. Keyrate stays one number with nothing attached: no accounts, themes or multiplayer.

Nothing gets pushed until the check script from v11 is green. That script is the first job.

## Where things stand

- **Web:** live at keyrate.jaybulb.com. The test runs at /app and sits under the landing hero. Rules live in `session.js`, the score math in `score.js`.
- **Shared scoring:** 30 score vectors in `vectors.json`. The web, Kotlin and Swift versions all have to agree on them.
- **Android and desktop:** Kotlin Multiplatform app in `kmp/`. Scoring is ported and tested in `kmp/shared`. It has never run on a device.
- **iPhone, iPad and Mac:** SwiftUI app in `apple/`, generated by xcodegen. It shares `tui/Sources/Score.swift` with the terminal app. The Mac build takes focus into the hidden field at launch. The iOS simulator has not been run, so the iOS keyboard and focus are still unverified.
- **Accessibility:** contrast is measured against WCAG levels. Screen reader labels and a result announcement are in place on the web and the native apps. Esc and the arrow keys move between modes on the web.
- **Store and signing:** Apple sign-in, Play sign-in, signing, notarizing, store listings and submits are Joshua's steps. The loop prepares them but does not do them.
- **Issues:** keyrate has no repo of its own. It lives in the labs repo, so there is no issue mirror.

## Next, in order

1. **v11, the check script.** One script that runs the node tests (`score`, `session`, `vectors`), the Kotlin tests in `kmp/`, the Swift tests in `apple/`, and checks the README references. It has to run green before any push, so write it first.
2. **v47, iOS focus.** If the keyboard does not rise on launch, fix the hidden field. This needs a simulator run, so keep it short and close the simulator after.
3. **v14, the paste rule.** Decide whether a pasted burst can set a best, write the answer down, then port it to all four versions. Pasted text is the most likely way to break the scoring, so QA it on each port.
4. **v19, word mode end.** Word mode should finish on the last character of the last word, the same in all four ports.
5. **v13 and v12, honest accuracy.** Show keystroke accuracy next to the final-text accuracy, then write the whitepaper section that explains both with a worked example.
6. **Accessibility and UI passes.** TalkBack (v26), VoiceOver (v50), Lighthouse at 100 on `/` and `/app` (v76), and the soft keyboard on Android (v21). Run each one, then fix what it finds.

After step 6, take the rest of the roadmap in order. Skip anything that needs Joshua's login or a store action, and note it in the roadmap instead.
