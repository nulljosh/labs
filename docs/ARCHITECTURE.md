# Architecture

Journal is a personal blog built with Jekyll, deployed via GitHub Pages. Posts are written as Markdown files in `_posts/`, organized by date. The site is static HTML generated from Markdown and Liquid templates. No backend, no database, no comments.

## How it runs

**Build:** Posts are stored as Markdown files (`_posts/YYYY-MM-DD-slug.md`). Jekyll reads the config (`_config.yml`), processes the Markdown through Liquid templates, and generates static HTML in `_site/`. GitHub Actions runs Jekyll automatically on every push to `main`.

**Deploy:** The built site is pushed to the `gh-pages` branch (or the Pages workflow handles it), and GitHub Pages serves it at `journal.heyitsmejosh.com`.

**Content:** Each post is a Markdown file with YAML front matter (title, date, tags, etc.). Posts are listed on the home page with excerpts and links. A theme toggle switches between light and dark modes via CSS variables.

## Structure

| File/Folder | What it owns |
|---|---|
| `_posts/` | All blog posts. Markdown files named `YYYY-MM-DD-slug.md`. YAML front matter includes title, date, tags, excerpt. Content is Markdown. Posts are sorted by date, newest first. |
| `_layouts/default.html` | Base template. Header, footer, navigation, theme toggle. All other layouts extend this. |
| `_layouts/home.html` | Home page layout. Post list with excerpts, date, tags. Extends default. |
| `_layouts/post.html` | Post page layout. Post title, date, tags, content, related posts. Extends default. |
| `_includes/` | Reusable HTML snippets. `header.html` (site nav), `footer.html` (footer), `post-list.html` (list of posts), `post-meta.html` (date/tags), `theme-script.html` (theme toggle JS), `theme-toggle.html` (toggle button). |
| `_includes/graphs/` | Dynamic graphs. `streak.html` renders a commit history streak visualization (fetches from GitHub API). |
| `_config.yml` | Jekyll config. Site title, URL, plugins, theme, build settings, gem dependencies. |
| `assets/css/main.css` | Main stylesheet. Layout, typography, light/dark theme via CSS variables. |
| `assets/` | Static assets. CSS, images, fonts. Copied into `_site/` during build. |
| `index.html` | Home page (alternative to `_layouts/home.html`; may be a redirect or alias). |
| `year.html` | Yearly archive page. Lists posts grouped by year. |
| `sw.js` | Service worker for offline support. Caches the blog shell and recent posts. |

## Theme and styling

| Feature | How |
|---|---|
| Light/dark mode | CSS variables and media query. `prefers-color-scheme` sets defaults; theme toggle button overrides via `data-theme` attribute on `<html>`. Persisted to `localStorage`. |
| Typography | System fonts (SF Pro, Helvetica). Responsive sizing. No custom fonts, no Google Fonts. |
| Responsive | Mobile-first. Flex layout. Adjusts for viewport size. |
| Colors | Design tokens from the house tokens.css (not duplicated here; could be shared). Blue and neutral tones. |

## Build and deployment

| Tool/File | Purpose |
|---|---|
| `.github/workflows/` | GitHub Actions. `test.yml` runs Jekyll build on every PR. Native-release.yml (if present) handles native app releases (not relevant for this Jekyll blog). |
| `Gemfile` / `Gemfile.lock` | Ruby dependencies. Jekyll, plugins, theme gems. `bundle install` installs them. |
| `.github/workflows/pages.yml` | (Auto-generated by GitHub) Runs Jekyll and deploys to Pages. |

## Scripts

| File | Purpose |
|---|---|
| `scripts/deploy.sh` | Deployment script. Builds the site and pushes to Pages (or runs `wrangler pages deploy` if hosted on Cloudflare). |
| `scripts/daily-scaffold.sh` | Scaffolds a new daily journal entry with today's date and template. Creates the Markdown file in `_posts/` with front matter. |
| `scripts/weekly-entry.sh` | Scaffolds a weekly entry. Aggregates the week's work for a consolidated post. |
| `scripts/graphs.py` | Generates data for the streak graph. Fetches commit history from GitHub and outputs JSON for `_includes/graphs/streak.html` to render. |
| `scripts/lint-posts.py` | Linter. Checks post front matter (required fields), filename format (YYYY-MM-DD), Markdown syntax, and enforces house writing rules (no em dashes, no jargon, etc.). |
| `scripts/sync-portfolio.sh` | Syncs the portfolio repo (`nulljosh.github.io`) with links to recent posts (optional, may not be in use). |

## Content guidelines

- **Posts are Markdown:** Write in Markdown, not HTML. Front matter (YAML) handles metadata.
- **No future dates:** Posts with `date` in the future are not published by default. Check `_config.yml` if future-dating is needed.
- **One entry per few months:** Per the house rules, entries are big (not daily logs). Consolidate related work into one entry.
- **URL slugs from filename:** The URL is derived from the filename (`YYYY-MM-DD-slug.md` → `/YYYY/MM/DD/slug/`). Don't slugify titles; keep it simple.
- **Plain English:** House writing voice. Prose, not bullet points. No em dashes, no jargon, no AI voice.

## How it differs from other blogs

- No comments (comments are gone; moderation costs more than the value they add)
- No feed reader optimization (RSS is supported by Jekyll but not hand-optimized)
- No CMS UI (posts are files, edited in a text editor; git is the version control)
- No dynamic content (everything is static HTML at build time)
- Static site generator (not a server running at request time)

## Gotchas

- **Timezone:** Post dates are in UTC by default (check Jekyll config). If a post is dated in the future relative to the server's timezone, it may not be published until the timezone catches up.
- **Rebuild on every push:** GitHub Actions rebuilds the whole site on every push, even if only one post changed. This is fine for a small blog but could be optimized with incremental builds.
- **No drafts:** There is no draft/unpublished concept in Jekyll by default. Either the post is in `_posts/` (published when built) or it's not. A workaround: posts dated in the future are skipped, so use a future date for drafts.
- **localhost testing:** Run `bundle exec jekyll serve` locally to test changes before pushing. The site rebuilds on file changes (with live reload if configured).
