# Evidna Technical Whitepaper

**v0.1.0** | October 2026

Evidna is an open-source computational biology lab. It connects public reference DNA to reproducible measurements and a small AI reasoning loop. The first study uses human HBB to teach coding substitutions and the boundary between a sequence observation and a functional claim.

## The core mechanic

Biopython reads a versioned GenBank reference.
The annotated coding sequence is extracted in its coding orientation.
A single substitution is validated against its 1-based reference coordinate.
The standard genetic code maps reference and changed codons to amino acids.
The output records the source accession and input-file SHA-256.
The deterministic calculation runs before any AI reasoning.

## First study

The bundled transcript is NM_000518.5, downloaded from NCBI.
Its CDS contains 444 bases, including the stop codon.
The reference translation contains 147 residues before processing.
The c.20A>T example changes GAG to GTG and encoded Glu7 to Val.
Traditional mature beta-globin numbering calls that residue Glu6.
The example is established biology, not a new discovery.

## Reasoning

Two sequential Claude Haiku calls implement researcher and skeptic roles.
They receive analysis results as context through the installed Claude CLI.
Tools, slash commands, and MCP servers are disabled for those calls.
The researcher proposes a hypothesis, computational test, control, and falsification criterion.
The skeptic identifies unsupported inferences and missing evidence.
Both outputs are saved as unvalidated text.

## Evidence memory

SQLite stores timestamped hypotheses and source-labelled observations.
Foreign keys preserve links between observations and hypotheses.
A revision requires an existing hypothesis and at least one attached observation.
It must use the same sequence fingerprint and variant.
The next AI proposal receives that prior evidence as context.
Old entries remain available; this is contextual revision, not weight training.
An observation is user-reported until independently checked.

## Interface and reproducibility

The CLI produces JSON and stores local notebooks outside version control.
A static landing page explores three reports generated by the same Python engine.
The browser does not execute Python, call a model, or accept genomic uploads.
A locked environment and unit tests cover calculations and notebook boundaries.
AI failure does not save a partial hypothesis.
No model credentials are embedded in the repository or landing page.

## Limits and next evidence

The initial parser requires one complete, unambiguous annotated CDS.
Only single-base substitutions and the standard genetic code are supported.
Start and stop changes are flagged; downstream expression is not inferred.
Sequence translation cannot establish folding, function, or clinical effects.
No structure model, autonomous discovery claim, or laboratory control is provided.
Future work begins with independent benchmarks and reviewed experiment records.
Instrument support needs a specific device, a qualified lab partner, and authorization.

320-pixel layouts without overflow, working controls, and keyboard access.

The biological check compares reference, c.20A>T, c.20A>G, and synonymous c.21G>A.
It reports sequence differences, average molecular mass, and estimated charge.
These are calculations on unprocessed protein sequences, not physical measurements.
The reference annotation provides a separate check of the translated protein.
The first AI proposal predicts roughly 30 Da lower mass and about +1 charge.
Its prediction was compared with calculation, without another model call.

Open gaps: independent biological benchmarks, hypothesis-quality evaluation,
structure/function evidence, evidence-file integrity, and reviewed experiment records.
Physical experiments and instrument automation remain future work.

The first proposal's roughly -30 Da and +1 predictions agree with these estimates.

All comparisons use unprocessed 147-residue chains with average molecular masses.

The synonymous control checks sequence-derived metrics, not expression or RNA effects.
The full output is `examples/hbb-study.json`; the notebook records it as an observation.
This is one completed computational check, not a novel biological discovery.

## Sources and what remains untested

[NCBI reference](https://www.ncbi.nlm.nih.gov/nuccore/NM_000518.5/) provides the annotated coding sequence.
[UniProt snapshot](https://rest.uniprot.org/uniprotkb/P68871.fasta) provides the protein cross-check.
[Biopython ProtParam](https://biopython.org/docs/latest/api/Bio.SeqUtils.ProtParam.html) defines the mass and charge calculations.
[ExPASy assumptions](https://web.expasy.org/protparam/protparam-doc.html) describe the limits of sequence-derived protein estimates.

No structural or functional experiment has been performed.
No evidence establishes that repeated AI revisions improve hypothesis quality.
Next research: evaluate a small panel of independently documented variants, then
compare predicted consequences with held-out observations using a fixed scoring rule.
Do not treat database agreement or internal unit tests as that validation.

## The unmatched cases sharpen the question

UniProt VAR_002941 records T51K. The reference codon is ACT; encoding lysine
requires at least two coding-base changes from that codon. A single-base scan
therefore cannot reproduce it. This is a computed scope limit, not a new finding.

VAR_035240 records V68D, traditionally beta-globin residue 67, in Hb Bristol.
[Rees and colleagues, 1996](https://pubmed.ncbi.nlm.nih.gov/8704193/) report a DNA
change encoding methionine and evidence of subsequent conversion to aspartate.
Translation alone cannot explain the final processed residue. The paper provides
an established biological explanation for one apparent annotation mismatch.
Evidna did not discover this mechanism or perform the cited experiments.

## Benchmark progress

`benchmarks/baseline.json` freezes input fingerprints and initial regression metrics.
Nine known sequence cases pass. Three scored cycles reproduce identical counts.
The median initial cycle is about 0.72 seconds on the development Mac.
Timing is informational; shared CI runners do not gate on wall-clock speed.
The public landing displays these results and preserves the unmatched cases.
This is software and sequence-concordance evidence, not a hypothesis-quality score.

## Held-out ClinVar benchmark (October 26, 2026)

The rule was written down and committed before any labels were fetched (`benchmarks/heldout-spec.json`). Inputs are ClinVar HBB records whose title is a single NM_000518.5 coding substitution. Pathogenic and likely pathogenic count as 1, benign and likely benign as 0, and everything else is excluded. Records are sorted by VCV accession, and the newest 30 percent are held out. Predictor v0 calls stop gains, stop losses and start-codon changes 1, synonymous changes 0, and a missense change 1 when its BLOSUM62 score is -2 or lower.

Of 1,972 pinned records, 93 qualify. Most HBB records are intronic, untranslated or larger changes, which this version excludes. The engine's translation agreed with ClinVar's stated protein change on all 93. On the 28 held-out records (24 positive, 4 negative), v0 reaches 0.67 balanced accuracy: sensitivity 0.58 and specificity 0.75. Both baselines score 0.50. With only four negatives, that difference is weak evidence. It sets a baseline for later predictors, which must be scored on the same split next to v0.

ClinVar classifications are submitter assertions, not measurements, and one gene says nothing about others.
