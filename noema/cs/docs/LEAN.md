# Busy Beaver in Lean 4

Everything `busy.py` settles at 2 and 3 states is also checked by Lean's kernel, with no `sorry`, no `native_decide`, and the axioms propext and Quot.sound only. `cd proofs && lake build` runs it. The README has the Python side.

Lean check. The 41 FAR certificates are also checked in Lean 4, with no `sorry` and no `native_decide`. `proofs/FarCerts/Basic.lean` defines a Turing machine run from blank, then proves once that any certificate passing a short list of local checks means the machine never reaches an undefined transition. A mirror lemma covers the 10 certificates found for the mirror image. `far_lean.py` turns each certificate into Lean data with witness sets, after checking that its local test agrees with `far.holds` on all 41 and rejects each one with acceptance flipped. Lean's kernel then runs every check by `decide`. `cd proofs && lake build` takes about 10 seconds, and each theorem uses only the standard axioms propext and Quot.sound. The proof covers those 41 holdouts only. The simulator and the other deciders that settle the rest of the 4-state machines are still checked only in Python. Coq-BB5 (2024) already checks FAR in Coq, so this is a second proof assistant, not a new result.

The cycle decider is checked in Lean too. `proofs/FarCerts/Cycle.lean` proves once that a run from blank which reaches the same configuration at steps i and i + p, with p > 0, never halts. `cycle_lean.py` collects the 532 machines that `busy.py` proves cyclic at 2 and 3 states, finds the first repeat in Lean's own configuration shape for each, and writes them as lists the kernel checks by `decide`. A wrong step count fails the build. The translated-cycler decider is checked the same way. `proofs/FarCerts/Translated.lean` proves that if, at step i, the head is on the right edge in state q reading a, and p > 0 steps from there never reach past the nearest d cells on its left and end on the right edge in state q reading a with those d cells unchanged, then the same p steps repeat forever, whatever lies further left. A left-moving cycler is checked on its mirror. `cycle_lean.py` finds (i, p, d) for all 3,063 translated cyclers at 2 and 3 states (1,573 on the mirror), and the kernel checks each by `decide`. So every 2- and 3-state machine that `busy.py` settles by a cycle or a translated cycle is proved in Lean, 3,595 in all.

The rest of the 3-state tree is in Lean too. The 92 machines `busy.py` settles with its tape deciders (backward, closed tape, block and n-gram) all have FAR certificates, found by `far.py` with at most 10 DFA states each and kept in `far-certificates-3.json`. `far_lean.py` exports them like the 4-state ones, and the same soundness theorem proves each never halts. The halting branches are checked by running: `proofs/FarCerts/Halt.lean` proves that reaching step k from blank with no rule to apply means the machine halts, and `cycle_lean.py` writes all 1,791 halting branches at 2 and 3 states with their step counts. A wrong count fails the build. `BB3.lean` checks that the longest 3-state halter takes 20 steps and halts on its 21st, the known BB(3) = 21. So every leaf of the 2- and 3-state trees, 5,478 machines, is settled in Lean.

BB(3) = 21 is now proved in full in Lean. `Tree.lean` and `Explore.lean` replay the 3-state tree inside Lean: run a partial machine from blank, and if it halts within 20 steps, try every way to define the missing rule. Two symmetries cut the tree as `busy.py` does: the first move goes right, since the mirror image halts at the same step, and a node that only uses state 0 never picks state 2, since renaming states 1 and 2 changes nothing. A machine that never halts within 20 steps must extend the next machine on one of the three lists proved never to halt. `explore_sound` turns a successful replay into the theorem, and `BB3Tree.lean` runs the replay over all 5,417 nodes by `decide`. The result, `FAR.bb3`, says one 3-state machine halts on step 21 and no 3-state machine that halts takes longer. It uses only the axioms propext and Quot.sound. Two sabotage tests fail as they should: drop one never-halting machine from a list, or allow only 19 steps, and `decide` reports false. `lake build` takes about 50 seconds, most of it the replay. Coq-BB5 (2024) already proved BB(2) to BB(5) in full, so this is a second proof assistant, not a new result. The 4-state cyclers would take hundreds of generated files. CI builds the whole Lean project on every push.

BB(2) = 6 is proved the same way, in `BB2Tree.lean`: the 2-state tree replays in Lean with the 2-state cycles and translated cyclers, and no FAR certificate is needed. BB(2,3) = 38 is proved in Lean too, on the same replay. `Tree.lean` and `Explore.lean` now take the alphabet size, the state count and the step bound as parameters, and BB(3) still builds from them unchanged. The state-renaming symmetry is only the swap of states 1 and 2, so the replay covers at most 3 states. `python3 cycle_lean.py 2x3` exports the 2-state, 3-symbol tree in `busy.py`'s order: 431 cyclers, 3,440 translated cyclers and 332 FAR certificates (the 330 the direct search settles plus the 2 backward reasoning settles, all found again by the direct search and kept in `far-certificates-23.json`). `BB23Tree.lean` replays the tree against those three lists by `decide`. `FAR.bb23` says the champion 1RB2LB1RZ_2LA2RB1LB halts after 37 steps, on the 38th, and no 2-state, 3-symbol machine that halts takes longer. It uses only propext and Quot.sound. The same two sabotage tests fail as they should. A full `lake build` needs about two minutes of CPU time. Coq-BB5 already proves S(2,3) in Coq, so this is a second proof assistant, not a new result. `Count2.lean` then counts in Lean: of all 20,736 tables with 2 states (12 choices per entry, as in A004147), 9,784 halt from blank and their halting steps add up to 13,504, so A004147(2) and A386859(2) are machine-checked. BB(2) is what makes the six-step search enough. At 3 states there are 16^6 tables, too many to list, so `CountSum.lean` and `CountTree.lean` prove once that the weighted tree counts every table: where a partial table first reaches an undefined entry, its 4 halting choices finish every completion at that step and each other choice is a child. `Count3.lean` then checks, with BB(3) as the step bound, that 7,571,840 three-state tables halt and their halting steps add up to 13,141,792 (A004147(3), A386859(3)), and that the halting times are exactly 1 to 21, so the runtime spectrum has 21 values. One kernel check of the whole tree needed 12 GB, so `python3 count_lean.py` cuts it into 182 pieces of at most 8,000 steps (`Count3G*.lean`), each checked alone, and the top of the tree reads their values in the order it meets them. Axioms propext and Quot.sound only. These values were known; the Lean proof is new.
