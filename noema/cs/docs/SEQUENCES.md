# Integer sequences from the machine tree

The same enumeration that settles Busy Beaver answers counting questions about all the halting machines, not just the record holder. Four OEIS sequences come out of it, three of them past where OEIS stops. The README has the deciders those counts rest on.

How long do all the halting machines run, added up? OEIS A386859 asks this for n states and 2 symbols, and lists four terms. `halters.c` walks the machine tree with weights. Each leaf is a run that reaches an undefined row and halts there, and it stands for every full machine that agrees with it on the rows the run used. It counts machines the way A004147 does: a row writes, moves and picks a state or halt, so there are 4(n+1) choices per row. For 1 to 4 states it gives A004147 and A386859 term for term, plus the Lazy Beaver values 72 for 4 states and 23 for 2 states with 3 symbols. A node that never reaches an undefined row is cut by an exact repeat of the whole tape, a shifted repeat between two record cells, backward reasoning, or an n-gram closed position set. Otherwise it runs to the step cap, which must be the proved BB value. The tests fire every cut early on the 4-state tree, and the counts do not move.

At 5 states the cap is 47,176,870. Six processes walked 48,379,894 leaves in about 3 hours. About 306,000 nodes ran to the cap. 3 left the 4 million cell buffer and were rerun on a 134 million cell tape, and none reaches an undefined row. The count is 26,751,695,615,616 halting machines, exactly A004147(5), which OEIS credits to a separate enumeration by Shawn Ligocki. A wrong cut could only make that count smaller. The sum of their halting times is 64,068,865,333,248, a fifth term for A386859. The 333 halting nodes past step 2,000 are listed in `halters-5.json`, and a separate simulator reran each one from blank. They account for the gap to a cap-2,000 run exactly, both in machines (63,936) and in steps (54,812,417,088). The same run answers a question Aaronson asks in The Busy Beaver Frontier (2020): how many distinct runtimes do n-state machines have? For 1 to 5 states the counts are 1, 6, 21, 79 and 1,207. A single run at cap 2,000 finds every halt up to step 2,000, which gives 919 of them, and the long halters give the other 288. The second-longest 5-state runtime is 23,554,764, a gap of 23,622,106 below BB(5), the value Aaronson gave while BB(5) was still a conjecture. With more symbols the cuts that read one bit per cell stay off, and the rest still work. 2 states and 3 symbols give 16,525,080 halting machines, 24,319,536 steps in all and 27 distinct runtimes. 2 states and 4 symbols, capped at S(2,4) = 3,932,964, give 54,440,511,648 halting machines, 84,150,017,280 steps in all and 155 distinct runtimes, with no run leaving the buffer. There is no published count to match here, but the Lazy Beaver values 23 and 93 match, and the second-longest 2-state, 4-symbol runtime is 7,195, the record Brady found in 1988. All of this rests on S(5) from Coq-BB5 and on the four cuts, which are argued and tested here but not proved in Lean. A second count: `runtimes.py` walks the same tree in plain Python with no deciders, cut only by the proved BB(n) cap, and shares no code with `halters.c`. It gets 1, 6, 21 and 79 distinct runtimes for 1 to 4 states, and the same halting counts and step sums; the first missing time at 4 states is 72, the Lazy Beaver number. At 2 states and 3 symbols it agrees too: 27 runtimes, 16,525,080 halters, 24,319,536 steps. At 5 states a third program, `plainwalk.c` (decider-free C, no code shared with `halters.c`), walks every machine to step 2000 in 14 minutes and gets the same 26,751,695,551,680 machines, 64,014,052,916,160 steps and 919 runtimes. Past step 2000 the list is complete for a counting reason: A004147(5), from Ligocki's separate enumeration, minus that count leaves exactly 63,936 machines, which is exactly the weight of the 333 long halters, each rerun from blank on its own.

Placid Platypus, the inverse question. What is the fewest states a machine needs to halt with exactly n ones on the tape? OEIS A399346 had n = 1 to 37. The walk that counts halters can also record the ones each one leaves, so `plainwalk.c` with a third argument lists every ones count a machine with n states can halt with, and one machine for each. Joined with the 333 halters past step 2000, the 5-state list is complete: 130 counts, every one from 0 to 73, then gaps, up to 4,098. So no 5-state machine halts with exactly 74 ones, the smallest such number. Harland (2006) named the problem; we found no published value past n = 37. A missing count gets a 6-state witness when a 5-state machine's halting row can be sent to a new state that adds the rest; `sixstate.c` tries this on up to 200 machines per count. `halters.c` with `ONES=1` gives the same 59 counts up to step 2000 from its own code, and the long halters' counts match every 5-state machine in Michel's survey. `python3 platypus.py` (about 30 minutes) does it all, reruns every witness from blank with a separate simulator, and writes `platypus-5.json`, which holds PP(n) and a witness machine for every n from 1 to 177. A 6 there means no 5-state machine prints n and the listed 6-state machine does. The lower bounds rest on the same completeness argument as the 5-state counts above; the upper bounds are explicit machines, each rerun from blank.

Three searches got it to 177, each picking up where the one before stopped. The extender reaches 130 from bases of 25 ones or more, and 176 once bases of 25 to 39 ones are included as well. `walk.c` takes a random walk through 6-state tables seeded with 5-state halters, and found 131 to 135 while the extender was still capped at 130. `nbhd.c` takes a known 6-state witness and tries every machine within one, two or three changed transitions, keeping the halters whose ones fall in a window. That is what gave 177: a depth-2 sweep over 122 known witnesses, and then four more terms from reseeding on its own finds.

Two things about running `nbhd.c` turned out to matter more than the search depth.

Keep every machine it prints, not one per ones count. A sweep prints every halter whose ones fall in the window, and the obvious thing is to record the first witness for each new count and drop the rest. Those dropped machines are the best seeds there are. After the sweeps above had kept 134 witnesses and discarded 4,205 other halters, one depth-1 pass over all 4,339 found 188 along with 23 other counts, after two depth-2 and two million-step depth-2 probes aimed straight at 188 had found nothing. Depth 1 over a wide pool beats depth 3 over a narrow one.

Flip the halting write before searching at all. Witnesses come in pairs, because the halting transition writes a 0 or a 1 and that single cell is the whole difference. Rewriting that one symbol on every machine already in hand costs one simulation each and gave five counts with no search.

Why the holes look the way they do. Of the 145 six-state witnesses at or above 130, 142 sit next to another witness, so the printable set is almost entirely adjacent pairs. That follows from the same halting write: a machine stops by writing a 0 or a 1 on one cell, so it comes with a sibling printing one more or one fewer. A hole is then not a near miss but a count no machine straddles. Around 178 the neighbours of every machine we held printed 176 and 177, or 179 and 180, two pairs with 178 sitting between them.

That observation is what closed 178, and it is the one worth keeping. A 178-printer has to be the sibling of a 177 or a 179, so the right search is not a wider one but a pointed one: collect the machines printing those two counts, and look two transition changes out asking for 178 and nothing else. Fifty-two distinct seeds gave ten hits, after a million-step probe and every general depth-2 sweep had come back empty. 179, 180 and 181 came with it, and the sequence ran on to 181 in one step. A hole says which machines to search from, not how much harder to search.

The step cap is worth raising too, but less than either of those. It found 256, 257 and the counts near 410, which need 59,257 and 192,000 steps, and then stopped paying: at a million steps it returns nothing a 200,000 cap had not already found.

182 is the first n left open, with 221, 222, 227, 228, 231, 232 and 246 to 251 behind it. A gap may still be real: a 6-state machine printing exactly that many ones could simply not exist, and settling that needs a proof about all 6-state machines, which is BB(6)-hard. A search can only ever find witnesses.

The OEIS edit, submitted 2026-10-28 and waiting on an editor, is written up in `docs/OEIS-A399346.md`.

Circular tapes. OEIS A394183 asks for the longest halting run of any 2-state machine on an n-cell circular tape, over every starting tape, and had n = 1 to 19. Turning the tape so the head stays at cell 0 leaves 2^(n+1) configurations per table, each with one successor, so `circular.c` walks that graph once with memory instead of simulating each start. It gives all 19 known terms and eight new ones, a(20) to a(27): 174, 253, 213, 300, 256, 351, 303, 406. A separate direct simulator confirms each new maximum on its best table. Odd terms fit the entry's formula (n+1)(n+2)/2, and every even term from 14 to 26 fits (n^2 - 3n + 8)/2, which the entry does not have. Results in `circular.json`; the OEIS edit waits for Joshua (`docs/OEIS-A394183.md`).

Rule 110 on a ring. OEIS A332717 lists the cycle lengths rule 110 can settle into on a ring of n cells, and A332718 counts them; both stopped at n = 21. Every configuration has one successor, so `rule110.c` walks all 2^n of them once with two bit sets and records each new cycle. It reproduces all 21 rows and gives rows 22 to 34; the counts run 10, 3, 11, 7, 8, 9, 15, 7, 14, 5, 12, 9, 12. Each row's longest cycle equals A204371(n), computed separately, all the way to 34, and a second program using Brent's cycle check agrees on rows 20 to 24. Results in `rule110.json` and `b332717.txt`; the OEIS edits wait for Joshua (`docs/OEIS-A332718.md`).

Sorting networks, the second study. How few comparators can sort n inputs? `sortnet.py` searches breadth first over the sets of 0-1 vectors a network can still output, which by the 0-1 principle is all that matters. It finds 0, 1, 3, 5, 9, 12 and 16 for n = 1 to 7 (7 takes about 80 seconds), matching OEIS A003075. That is a reproduction, not new work. The plain search will not reach 9 inputs, where Codish, Cruz-Filipe, Frank and Schneider-Kamp (2014) proved 25 with symmetry and subsumption pruning.
